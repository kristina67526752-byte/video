# Эксперимент: целостность данных наземного обслуживания ВС (версия 3.3)

Воспроизводимый модельный эксперимент к статье «Метод выявления нарушений целостности данных о
наземном обслуживании воздушных судов». Версия 3.3 (10.11.2026) — исправления по рецензии
10.11.2026; ответы — `../3-otvety-i-materialy/otvety-na-retsenziyu-2026-11-10.docx`.

Что изменено в коде относительно версии 3.1 (числа изменились, сравнивать с 3.1 нельзя):

- **Готовность D1** выводится из модели процесса (`model.d1_preds`): уборка, бортпитание,
  обслуживание водой, погрузка багажа и заправка, если меры безопасности не подтверждены. Раньше
  в условии не было воды и погрузки.
- **Монитор Б3** получает те же правила, что и П, включая подтверждение `SAF` и сверку со
  справочными значениями. Б3 — тот же код в другом режиме, а не сторонний инструмент.
- **Подтверждение `SAF`** должно прийти до начала заправки; более позднее исключения не даёт.
- **Генератор**: потеря связи и задержка исправления — с экспоненциальным хвостом, без жёсткой
  границы; 10 % ошибок ввода не исправляются; в 5 % заправок с пассажирами подтверждение вводится
  после начала заправки, в 2 % не вводится.
- **V2-start**: метка сдвигается назад или вперёд; во втором случае задерживается и сообщение
  (раньше метка всегда оказывалась «из будущего» и её ловила проверка времени).
- **Показатели**: три группы подвидов (по построению, содержательные, вне возможностей метода),
  разброс между выборками, время до тревоги, доля тревог, связанных с нарушением.
- **Сутки**: добавлен «тихий» нарушитель (15 % отметок агента выхода).
- Сетка допусков расширена; окно ожидания W ограничено 15 мин (`run.W_MAX`): критерий калибровки
  не учитывает задержку тревоги. Компромисс «окно — полнота — задержка» на широкой сетке —
  `results/tradeoff_W.json`, все её точки — `results/calibration_grid_wide.csv.gz`
  (оба файла строит режим `--tradeoff`).
- 13 тестов, в том числе на условие D1, запоздавшее подтверждение мер безопасности и
  разбиение подвидов на группы.

> **Все данные синтетические.** Реальные или обезличенные журналы не использовались.
> Параметры процесса (длительности, источники, доли отклонений, время проверки) — допущения из
> `gh_integrity/model.py`. Основная модель процесса (29 зависимостей) построена по модельному графу
> [Головченко, Асмоловская], прежняя (27 зависимостей) — вариант; сопоставление — `../3-otvety-i-materialy/sopostavlenie-modeley.docx`.

## Запуск

```bash
pip install -r requirements.txt     # точные версии, с которыми получены результаты
python -m pytest -q tests           # 13 тестов, ≈2 с
python -m gh_integrity.run          # полный прогон, ≈25 мин на одном ядре
python -m gh_integrity.run --tradeoff  # компромисс «окно W — полнота — задержка», ≈20 мин
python -m gh_integrity.run --quick  # сокращённый прогон для проверки, ≈2 мин
```

Проверено с Python 3.13, numpy 2.5.3, matplotlib 3.11.2, Pillow 12.3.0 (версии записываются в
`results/summary.json`, поле `environment`; версия эксперимента — поле `version`). Повторный
запуск даёт те же числа: все случайные величины берутся из `numpy.random.default_rng(seed)`.

## Что делает прогон

1. **Калибровка** (выборка `seed=0`: 600 штатных оборотов и по 100 оборотов с нарушениями V1–V5)
   для П, Б2 и Б3: выбирается вариант допусков с наибольшей полнотой при доле ложных тревог не
   выше 5 %; все точки сетки — `results/calibration_grid.csv` (кривые «ложные тревоги — полнота»).
2. **Проверка** на 10 независимых выборках (`seed=1..10`) по 600 штатных оборотов и по 100
   оборотов каждого из восьми видов нарушений: всего 14 000 оборотов. Для сравнения П прогоняется
   без правил доверия (`P_v2`: признак заправки с пассажирами и количества берутся из отметок).
3. **Последствия**: исходы решений D1 и D2 с моментом решения; задержки с учётом ручных проверок
   (`check_time`); нагрузка на смену; момент выявления относительно фактических решений;
   условные категории последствий по реконструкции состояния на момент ложного решения;
   парное сравнение с П.
4. **Бюджеты ложных тревог** 2,5; 5 и 10 %; **чувствительность** к окну W, запаздыванию отметок,
   неучтённым вариантам и доле α минимальной длительности; **согласованность модели процесса**:
   данные и правила по основной модели и по графу [Головченко, Асмоловская] (2 × 2);
   **контрольный опыт** с подменой признака safety (рецензия 08.11.2026).
5. **Сутки работы аэропорта** (`gh_integrity/campaign.py`): 100 суток по 180 оборотов. Атаки с
   12:00 (терминал агента выхода, заправщика или службы уборки; подлог окончания V1b или ложный
   признак заправки с пассажирами V7a) и неисправности без атаки (часы, связь, счётчик топлива).
   Подозрение на источник — правило «K оборотов за 6 ч» (K = 2…5) и CUSUM с порогом, подобранным
   на 50 отдельных сутках без атаки; ущерб — ложные решения до подозрения по времени решения;
   модель блокировки (предотвращённые решения, перепроверка, ручные подтверждения).
6. **Таблицы и рисунки** — в `results/` и `figures/`.

## Методы

| Код | Название | Правила |
|---|---|---|
| Б1 (`B1`) | проверка полей | F: окно рейса, диапазоны значений, отсев повторной доставки по `msg_id` |
| Б2 (`B2`) | проверка полей и меток времени | F + T |
| Б3 (`B3`) | монитор декларативных ограничений (RV-LTL, MP-Declare) | F + T + R1–R4, те же правила доверия; нарушение сообщается, если сохраняется β мин; ожидаемые обязательства решение не задерживают |
| П (`P`) | предложенный метод | F + T + R1–R4, окна W и H, удержание решения при любом несоответствии, модель доверия |
| `P_v2` | П без правил доверия | признак заправки с пассажирами и количества берутся из отметок (для сравнения) |
| `P-…` | абляция | П без одной группы правил |

Правила доверия: исключение при заправке с пассажирами снимает две зависимости только при
подтверждении мер безопасности `SAF` с отдельного рабочего места (роль `SUPV` — экипаж или
координатор оборота), полученном до начала заправки или не позже чем через δp после него; нормы длительности — по справочным значениям рейса (`Case.refs`), количества в
отметках сверяются с ними. Параметры `safety_trust="manual"`, `trusted_norms=False` отключают
эти правила (вариант `P_v2`).

## Виды нарушений

| Код | Нарушение | Подвиды |
|---|---|---|
| V1 | ложное завершение операции | `V1a` подлинная отметка тоже приходит; `V1b` подлинная отметка подавлена |
| V2 | изменение временной метки | `V2-end`, `V2-start` |
| V3 | повтор сообщения | `V3a` с исходной меткой времени; `V3b` с новой меткой |
| V4 | пропуск сообщения | `V4-start`, `V4-end` |
| V5 | нарушение последовательности | `V5a` фактическое; `V5b` только в данных |
| V6 | согласованная подмена отметки заправки и показаний счётчика (граница применимости) | — |
| V7 | подмена поля, ослабляющего контроль | `V7a` ложный признак заправки с пассажирами; `V7b` то же с подложным подтверждением `SAF` (два источника); `V7c` занижение числа пассажиров или массы топлива под норму |
| V8 | правдоподобная ранняя отметка осведомлённого исполнителя: в допусках правил, на операциях без независимого источника (граница применимости) | — |

Метрика «нарушения целостности» — все виды, кроме `V5a` (фактическое нарушение порядка работ, а не данных).

Обнаружение — тревога не раньше внесения нарушения, которой нет у «двойника» (`Case.twin_messages`).
Дополнительно рассчитывается обычная матрица ошибок по любой тревоге (`tp_any`, `recall_any`).

В статью входят `fig1_process_model` (рис. 1) и `fig3_detection_by_type` (рис. 2); их копии —
в `../2-risunki/`. Остальные рисунки дополнительные: `fig2_example_case` — пример оборота, где Б2
по подложной отметке окончания загрузки объявляет готовность к посадке, а П удерживает решение
и выдаёт тревогу; `fig4_sensitivity` — чувствительность; `fig5_campaign_day` — сутки с атакой.
Рисунки по готовым результатам перестраивает `python -m gh_integrity.figures` (кроме `fig5`).

D1 — готовность к посадке пассажиров, D2 — все операции обслуживания завершены; это
информационные статусы для диспетчера. Исход `false` — готовность объявлена по данным раньше
фактической; `manual` — решение после ручной проверки по тревоге.

В статье уровни нарушителя обозначены А1–А3, категории последствий — С1–С4; в файлах результатов
категории записаны как К, В, С, Н (С1 = К, С2 = В, С3 = С, С4 = Н).
