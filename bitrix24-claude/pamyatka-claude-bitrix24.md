# Памятка: подключение Claude к Битрикс24 через входящий вебхук

**Вариант Claude:** Claude Code в облачной сессии (claude.ai/code). Claude вызывает REST API Битрикс24 командами `curl` через **свой** входящий вебхук сотрудника.
Официальный MCP-коннектор Битрикс24 и настройка портала «Работа с Битрикс24 из внешних AI-систем» **не нужны**.

Обозначения: ✅ — шаг выполнен и проверен лично; ⚠️ — шаг не проверен, описан по документации.
Все значения в угловых скобках (`<портал>`, `<ID задачи>`) — заглушки. Настоящие адреса и ключи в памятку, задачи, чаты и скриншоты не вставлять.

## 1. Какие нужны доступы

| Что | Где взять |
|---|---|
| Учётная запись на портале `<портал>.bitrix24.ru`, свои задачи | выдаёт ГД / отдел кадров |
| Разрешение создавать входящие вебхуки | если пункта «Входящий вебхук» нет — просить ГД проверить **это разрешение** (права администратора не нужны) |
| Аккаунт claude.ai с доступом к Claude Code | выдаёт ГД |
| Облачное окружение Claude Code, где разрешён домен портала | настраивает сам сотрудник (п. 2.2) |

## 2. Подготовка

**2.1. Создать свой входящий вебхук** ✅
Битрикс24 → «Разработчикам» → «Другое» → «Входящий вебхук». В блоке **«Настройка прав»** выбрать только **«Задачи (task)»** и **«Пользователи (user)»** и обязательно нажать **«Создать»** внизу окна (при изменении — «Сохранить»). Пока кнопка не нажата, вебхук работает без прав.
Адрес вида `https://<портал>.bitrix24.ru/rest/<ID пользователя>/<секретный ключ>/` — **секрет, равный паролю**: по нему можно действовать от вашего имени и с вашими правами. Чужие вебхуки не использовать.

**2.2. Настроить окружение Claude Code**
claude.ai/code, **стартовый экран** (где начинают новую сессию) → над полем ввода кнопка с облаком и названием окружения (например, *Default*) → **Облако** → навести на окружение → значок шестерёнки справа. Значок облака в заголовке уже открытой сессии только показывает окружение, изменить там нельзя. ✅
- **Network access** → *Custom* → в поле **Allowed domains** написать `<портал>.bitrix24.ru`; отметить *Also include default list of common package managers* → сохранить. Начинает действовать и в открытой сессии через 1–2 минуты. ✅
- Адрес вебхука не вставлять в чат, а сохранить в окружении: раздел *Network secrets* (тарифы Pro/Max) или поле *Environment variables* строкой `B24_WEBHOOK_URL=<адрес вебхука>` (адрес заканчивается на `/`). Переменная видна всем, кто пользуется окружением, поэтому окружение должно быть личным; сессия подхватывает её при **новом** запуске. ⚠️
- Если окружение в разделе *Organization* — оно общее и только для чтения: менять его должен владелец, писать ГД. ⚠️

## 3. Подключение и проверка ✅

1. Открыть сессию Claude Code в настроенном окружении.
2. Отправить проверочный запрос:

   > Проверь подключение к Битрикс24 через мой вебхук: вызови методы `scope`, `user.current` и `tasks.task.get` для задачи `<ID задачи>`. Покажи список прав, мой ID, название и срок задачи. Адрес вебхука не выводи. Ничего не изменяй.

3. **Признак успешной работы:** `scope` возвращает `task, user`; `user.current` — ваш ID; по своей задаче видны название, статус, срок и описание. Ошибок нет.

## 4. Затруднения и проверенные решения

| Симптом | Причина | Что делать | Статус |
|---|---|---|---|
| Официальный коннектор: «Доступ через MCP-сервер закрыт» | на портале выключена работа из внешних AI-систем | не включать; работать через вебхук (решение ГД) | ✅ |
| `curl: CONNECT tunnel failed, response 403` | домен портала не разрешён в окружении Claude Code | п. 2.2: добавить домен в Allowed domains, подождать 1–2 минуты | ✅ |
| `insufficient_scope` на любой запрос, `scope` возвращает пустой список | вебхук не сохранён или у него не выбраны права | в форме вебхука выбрать «Задачи (task)» и «Пользователи (user)», нажать «Создать»/«Сохранить» | ✅ |
| Комментарии не читаются: `task.commentitem.getlist` возвращает 0, чтение чата — `insufficient_scope` | обсуждение идёт в «Чате задачи», для него нужно право `im` | указать ограничение в отчёте; право `im` — только по согласованию с ГД | ✅ ограничение подтверждено |
| Нет пункта «Входящий вебхук» | нет разрешения на создание вебхуков | написать ГД (см. табл. 1) | ⚠️ |
| `ACCESS_DENIED` или пустой ответ по задаче | вы не участник этой задачи | работать только со своими задачами | ⚠️ |
| `Invalid request credentials` / 401 | ключ неверный или перегенерирован | взять актуальный адрес в форме вебхука, обновить `B24_WEBHOOK_URL` | ⚠️ |

**Если адрес вебхука попал в чат, задачу или на скриншот:** в форме вебхука нажать **«Перегенерировать»** — старый адрес перестанет работать; новый сохранить в окружении.

## 5. Примеры запросов (только чтение, на своей задаче) ✅

**5.1. Понять постановку**

> Прочитай задачу `<ID задачи>` в Битрикс24 (метод `tasks.task.get`) и комментарии к ней, если они доступны. Ничего не изменяй. Кратко изложи: цель, ожидаемый результат и критерии приёмки, срок, ограничения, что уже сделано, и какие вопросы стоит задать постановщику. Если комментарии недоступны — так и напиши.

**5.2. Составить план выполнения**

> По задаче `<ID задачи>` составь план выполнения: шаги с оценкой времени, что нужно от других людей, риски и точки проверки, чтобы успеть к сроку. В Битрикс24 ничего не записывай.

**5.3. Подготовить отчёт о результате**

> Подготовь черновик итогового комментария к задаче `<ID задачи>` в формате: сделано / проверено самостоятельно / не проверено / нужно решение (не больше трёх вопросов, к каждому — мой вариант решения). Не публикуй — покажи текст мне.

Комментарии из «Чата задачи» Claude через этот вебхук не видит — важные договорённости из чата вставляйте в запрос сами (без секретов).

## 6. Ограничения доступа и правила

- Вебхук действует **с правами владельца**: Claude видит только те задачи, к которым у вас есть доступ, и только методы из выбранных прав вебхука.
- Запросы на запись (комментарий, смена статуса, файлы) — только по явной просьбе и только в своих задачах. Чужие задачи не менять.
- Пароли, ключи, адреса вебхуков и персональные данные — не в тексте, не в примерах, не на скриншотах.
- Памятку не публиковать в общей ленте без согласования с ГД.
