# Памятка: подключение Claude к Битрикс24 через входящий вебхук

**Вариант Claude:** Claude Code в облачной сессии (claude.ai/code). Claude вызывает REST API Битрикс24 командами `curl` через **свой** входящий вебхук сотрудника.
Официальный MCP-коннектор Битрикс24 и настройка портала «Работа с Битрикс24 из внешних AI-систем» **не нужны**.

Обозначения: ✅ — шаг выполнен и проверен лично; ⚠️ — шаг не проверен, описан по документации.
Все значения в угловых скобках (`<портал>`, `<ID задачи>`) — заглушки. Настоящие адреса и ключи в памятку, задачи, чаты и скриншоты не вставлять.

## 1. Какие нужны доступы

| Что | Где взять |
|---|---|
| Учётная запись на портале `<портал>.bitrix24.ru`, свои задачи | выдаёт ГД / отдел кадров |
| Разрешение создавать входящие вебхуки | если пункта «Входящий вебхук» нет — просить ГД проверить **это разрешение** (права администратора не нужны) |
| Аккаунт claude.ai с доступом к Claude Code | выдаёт ГД |
| Облачное окружение Claude Code, где разрешён домен портала | настраивает сам сотрудник (п. 2.2) |

## 2. Подготовка

**2.1. Создать свой входящий вебхук** ✅
Битрикс24 → «Разработчикам» → «Другое» → «Входящий вебхук» (в разных версиях интерфейса путь может немного отличаться).
Права: только то, что нужно для работы с задачами, — «Задачи (task)» и «Пользователи (user)». Лишние права не добавлять. Сохранить.
Адрес вида `https://<портал>.bitrix24.ru/rest/<ID пользователя>/<секретный ключ>/` — **секрет, равный паролю**: по нему можно действовать от вашего имени и с вашими правами. Чужие вебхуки не использовать.

**2.2. Настроить окружение Claude Code** ⚠️
claude.ai/code → над полем ввода кнопка с облаком и названием окружения (например, *Default*) → **Cloud** → навести на окружение → значок шестерёнки справа → окно **Edit environment**:
- **Network access** → *Custom* → в поле **Allowed domains** написать `<портал>.bitrix24.ru`; отметить *Also include default list of common package managers* → сохранить. Действует и в уже открытой сессии примерно через минуту.
- Адрес вебхука сохранить в разделе *Network secrets* (есть только на тарифах Pro/Max) или в поле *Environment variables* строкой `B24_WEBHOOK_URL=<адрес вебхука>` (адрес заканчивается на `/`). Переменная видна всем, кто пользуется окружением, поэтому окружение должно быть личным. Переменную сессия подхватывает при **новом** запуске.
- Если окружение в разделе *Organization* — оно общее и открывается только для чтения: менять его должен владелец, писать ГД.

## 3. Подключение и проверка

1. Открыть новую сессию Claude Code в настроенном окружении. ⚠️
2. Отправить проверочный запрос: ⚠️

   > Проверь подключение к Битрикс24 через вебхук из переменной `B24_WEBHOOK_URL`: вызови методы `scope` и `user.current`. Покажи только список прав и мой ID. Адрес вебхука не выводи. Ничего не изменяй.
3. **Признак успешной работы:** в ответе есть список прав (`task`, `user`) и ваш ID пользователя, ошибок нет; затем Claude читает название и срок вашей задачи по запросу из п. 5.1.

## 4. Затруднения и проверенные решения

| Симптом | Причина | Что делать | Статус |
|---|---|---|---|
| Официальный коннектор: «Доступ через MCP-сервер закрыт» | на портале выключена работа из внешних AI-систем | не включать; работать через вебхук (решение ГД) | ✅ наблюдали |
| `curl: CONNECT tunnel failed, response 403` | домен портала не разрешён в сетевой политике окружения Claude Code | п. 2.2: добавить домен в Allowed domains, подождать минуту | ✅ ошибка наблюдалась; ⚠️ решение не проверено |
| Нет пункта «Входящий вебхук» | нет разрешения на создание вебхуков | написать ГД (см. табл. 1) | ⚠️ |
| `insufficient_scope` | у вебхука нет нужного права | открыть свой вебхук, добавить право `task` | ⚠️ |
| `ACCESS_DENIED` или пустой ответ по задаче | вы не участник этой задачи | работать только со своими задачами | ⚠️ |
| `Invalid request credentials` / 401 | ключ неверный, вебхук удалён | создать новый вебхук, обновить `B24_WEBHOOK_URL` | ⚠️ |
| Claude не видит комментарии | в новой карточке задачи обсуждение идёт в «Чате задачи», метод `task.commentitem.getlist` его может не вернуть; для чата нужно право `im` | указать ограничение в отчёте; право `im` добавлять только по согласованию с ГД | ⚠️ |

**Если адрес вебхука попал в чат, задачу или на скриншот:** удалить этот вебхук в Битрикс24, создать новый и обновить секрет в окружении.

## 5. Примеры запросов (только чтение, на своей задаче)

**5.1. Понять постановку** ⚠️

> Прочитай задачу `<ID задачи>` в Битрикс24 (метод `tasks.task.get`) и комментарии к ней, если они доступны. Ничего не изменяй. Кратко изложи: цель, ожидаемый результат и критерии приёмки, срок, ограничения, что уже сделано по комментариям, и какие вопросы стоит задать постановщику. Если комментарии недоступны — так и напиши.

**5.2. Составить план выполнения** ⚠️

> По задаче `<ID задачи>` составь план выполнения: шаги с оценкой времени, что нужно от других людей, риски и точки проверки, чтобы успеть к сроку. В Битрикс24 ничего не записывай.

**5.3. Подготовить отчёт о результате** ⚠️

> Подготовь черновик итогового комментария к задаче `<ID задачи>` в формате: сделано / проверено самостоятельно / не проверено / нужно решение (не больше трёх вопросов, к каждому — мой вариант решения). Не публикуй — покажи текст мне.

## 6. Ограничения доступа и правила

- Вебхук действует **с правами владельца**: Claude видит только те задачи, к которым у вас есть доступ, и только методы из выбранных прав вебхука.
- Запросы на запись (комментарий, смена статуса, файлы) — только по явной просьбе и только в своих задачах. Чужие задачи не менять.
- Пароли, ключи, адреса вебхуков и персональные данные — не в тексте, не в примерах, не на скриншотах.
- Памятку не публиковать в общей ленте без согласования с ГД.
